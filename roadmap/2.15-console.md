# 2.15 — The console

The page people actually live in. It has had the most attention already — the
terminal is themed through xterm's own options, the stat blocks are two columns
on a phone — and it still has the most left to give.

## What ships

### Stat tiles

The six blocks above the console are labelled text in a rounded box. They become
tiles: an icon square in the theme's accent, the label small above, the figure
large below. Two, three or six across depending on the window.

The icons are chosen by which block it is — CPU, memory, disk, name, status,
address — matched on position, since Pelican does not label them for us. That is
a structural bet and it fails safe: no icon, and the tile is what it is now.

**A setting to hide them.** On the console page, the console is the point.
Someone who knows their server's address does not need it in front of them every
time, and hiding all six gives the terminal another 120 pixels.

### Terminal settings of its own

The terminal is drawn on a canvas from xterm's options, which the plugin already
intercepts. That interception can carry more than colours:

| Setting | Why |
| --- | --- |
| **Font family** | A console font is personal, and the panel's is not everyone's |
| **Font size** | Already adjusted on a phone; make it a choice everywhere |
| **Line height** | Dense for reading a crash, loose for watching a boot |
| **Scrollback** | How far back the buffer keeps |
| **Cursor** | Block, bar or underline; blinking or not |

### Terminal colour schemes

The theme currently derives the terminal's colours from the accent. A dropdown of
schemes people already know their way around — and **Follow theme** stays the
default, because that is why the interception was built.

Each scheme is sixteen ANSI colours plus a background and a foreground, handed
to xterm the same way the accent already is.

### Fullscreen

A button in the page header, injected at
`panels::page.header.actions.before` scoped to the console page. It takes the
terminal to the full viewport — the console page, minus everything that is not
the console.

Escape leaves. It is CSS and a class on `<html>`; nothing about the terminal's
connection changes, so a server that is mid-boot stays mid-boot.

### Command bar

Small things that add up: the command input at 16px so a phone does not zoom into
it (already done), a monospace font matching the terminal, and the send button
where a thumb can reach it.

## How

- Tiles, hiding, fullscreen: CSS plus one render hook for the button.
- Terminal settings and schemes: the existing `window.Xterm` interception in
  `resources/inline/runtime.js`, which already merges a theme into the options
  before Pelican constructs the terminal. It is the right place for all of it,
  and it is worth remembering *why* it is there rather than in CSS — xterm draws
  to a canvas from its own options, so a stylesheet moves the text and leaves the
  glyphs behind.

## Risks

**Font size and the fit addon.** xterm computes its rows and columns from the
container and the font. Changing the size at construction is fine — it already
happens on a phone — but a size that is changed *later* needs a refit, and the
refit is Pelican's, not ours. So these are construction-time settings, applied on
the next page load, and the settings page has to say so.

**Scrollback costs memory.** A large buffer on a chatty server is real memory in
someone's browser. Cap it, and say what the cap is.

## Done when

- Every terminal setting survives a Livewire navigation to another page and back.
- Fullscreen leaves the websocket alone — a server booting while you toggle it
  keeps booting.
- Hiding the stat tiles gives the terminal the space, rather than leaving a gap.
- Nothing here is required: **Follow theme** and the current layout stay the
  defaults.
